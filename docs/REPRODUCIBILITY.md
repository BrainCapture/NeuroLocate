# Reproducibility

Everything the README claims is backed by a file in this repository. This page
says which file, and what to run to regenerate it.

## Supported environment

| | |
| --- | --- |
| OS | Linux x86-64 (developed and measured on Debian 12) |
| Python | 3.11 |
| package manager | [`uv`](https://docs.astral.sh/uv/) — `make setup` fails early without it |
| accelerator | none; everything below is CPU-only |
| container runtime | only for `make build` and `make test-images` |
| network | only during `make setup` |

OpenMEEG's OpenMP scaling is pathological on a many-core host: the per-call source
assembly is roughly 67x slower at 48 threads than at 8. The Makefile therefore
pins `OMP_NUM_THREADS=8` and gets throughput from processes rather than threads.
Do not remove that.

## Clean setup

```bash
git clone <this repository> && cd NeuroLocate-showcase
make setup
```

`make setup` creates `.venv` with Python 3.11 and installs, in order: the
NumPy-only `neurolayout_shared` package, the application with its `dev` extra
(which pulls in `pytest`, `scipy`, `openmeeg`, `mne`, `nibabel`, `matplotlib`),
and a CPU-only `torch` from PyTorch's own index.

`mne` is only needed to *generate* artifacts offline — the observation set and
the cached head model. Nothing in the demo, the benchmark or either container
image uses it.

## The demo

```bash
make demo         # about 60 s, offline
```

Runs `scripts/demo.py` on `h-k2-shared-close`, trial 4, and prints three
worst-source errors. It reads:

- `results/hybrid/observations.npz` — the committed 64-channel EEG for the whole
  matrix, generated by MNE's ico4 BEM at a skull conductivity the estimators do
  not assume, with the electrodes displaced;
- `components/tesseracts/proposal/proposal.pt` — the trained network, packaged
  inside its component;
- `components/shared_code/neurolayout_shared/artifacts/fsaverage_ico3_1005_64.npz`
  — the cached OpenMEEG head model the refinement inverts with.

It writes `results/demo.json` (a run output, not an artifact) and is
deterministic on a fixed host. `tests/test_demo.py` runs it and checks the three
errors against the frozen shard within the same tolerance the visual build uses:
0.05 mm on positions, 1e-4 on the relative sensor residual.

Expected runtime, 8 OpenMP threads: proposal 0.07 s, each of the two refinements
20–30 s.

## Tests

```bash
make test         # about 8 minutes, no container runtime needed
```

| file | gate |
| --- | --- |
| `test_component_cases.py` | every packaged JSON case, executed in-process |
| `test_gradient_headfield.py` | the sphere-backend VJP against central differences of the served `apply` |
| `test_source_vjp.py` | the OpenMEEG position and moment VJPs, with a step-size sweep |
| `test_batched_headfield.py` | `localize_batch` against the per-entry loop, in value and gradient |
| `test_openmeeg_physics.py` | OpenMEEG on concentric spheres against the analytic solution |
| `test_openmeeg_geometry.py` | channel order, zero channel mean after referencing, frame and scale |
| `test_localization.py` | a JAX loss over the served component; finite, non-zero gradients; the source moves toward the truth |
| `test_hybrid_compose.py` | the composed `proposal` → `headfield` gradient against central differences of the same composed forward |
| `test_hybrid_provenance.py` | the committed freeze matches the source; the component network matches the orchestrator's |
| `test_frozen_results.py` | the committed shards still aggregate to the published numbers |
| `test_image_transport.py` | image-backed components against in-process, and the composed gradient through both images (skipped without Docker) |
| `test_demo.py` | the demo reproduces the three frozen errors |

On its first run the suite builds `results/dipole_dictionary.npz` — a ~31 MB
cache of the OpenMEEG gain over the whole ico5 source space, about two minutes of
solver time — so that the MNE baselines provably run on NeuroLocate's physics
rather than MNE's own. It is a cache, not an artifact: it is ignored by git and
reused on every later run.

`test_image_transport.py` skips itself with an explicit reason when Docker is
absent or the images have not been built. A silently skipped container gate is as
bad as no container gate, so the reason names which precondition failed.

## Building the components

```bash
make build        # needs a Docker-compatible runtime
make test-images
```

`make build` runs `tesseract build` on `components/tesseracts/proposal` and
`components/tesseracts/headfield`, producing `neurolayout_proposal:latest` and
`neurolayout_headfield:latest`. The two images share no dependency tree: one
carries CPU-only PyTorch and has never heard of OpenMEEG, the other carries
OpenMEEG's compiled stack and has never heard of PyTorch or JAX.

`make test-images` runs every `components/tesseracts/*/test_cases/*.json` against
the built images with `tesseract run <image> test @<file>`. Each case freezes an
endpoint's inputs and its outputs with an explicit tolerance, so the same case
either passes in both transports or fails loudly in one. Regenerate them with
`make gen-tests`, and review the diff — regenerating is only correct when the
change in behaviour was intended.

| component | packaged cases |
| --- | --- |
| `headfield` | `apply.json`, `apply_zero_vector_raises.json`, `localize_apply.json`, `localize_vector_jacobian_product.json`, `vector_jacobian_product.json` |
| `proposal` | `apply.json`, `vector_jacobian_product.json` |

Once the images exist, `make test` also exercises the container boundary.

## Regenerating the artifacts themselves

None of this is needed to check the published numbers. It is here so the frozen
artifacts are not black boxes.

```bash
make observations   # rebuild results/hybrid/observations.npz (needs MNE, ~2 min)
make benchmark      # re-run every method over the matrix (hours, resumable)
make gradcheck      # the composed derivative check (~2 min)
make batching       # what the batched component path costs
make vjp-report     # the position-VJP step-size sweep
make summary        # re-aggregate and print
make figures        # the benchmark figure
```

`make benchmark` runs six of the seven methods. The seventh,
`hybrid_stopgrad`, is a training-ablation control that needs a second network
checkpoint produced by a fine-tuning run; that checkpoint is not part of this
repository, and its results are present in the committed shards. Re-running is
resumable at condition granularity — the runner skips a shard that already
exists — so an interrupted sweep costs one condition, not the sweep.

## What training the network involved, and where that code is

The packaged checkpoint `components/tesseracts/proposal/proposal.pt` is the
output of three offline stages, none of which is part of this repository's
runnable surface:

1. an OpenMEEG **gain bank** — 240,000 continuous source positions, each
   assembled once and re-solved into six plausible head models (brain-to-skull
   ratio 25:1 to 91:1, and small electrode displacements), about an hour and
   1.1 GB;
2. **supervised pre-training** on synthetic observations drawn from that bank —
   200,000 steps at batch 128, about 87 minutes on a GPU
   (`results/hybrid/training.json` holds the history);
3. a short **through-solver fine-tune**, in which `dL/dweights` of a loss defined
   downstream of the OpenMEEG BEM reaches the optimizer — and its stop-gradient
   control, which is where the `hybrid_stopgrad` arm's checkpoint comes from
   (`results/hybrid/finetune_physics.json` and `finetune_stopgrad.json`).

The modules those stages use — `neurolayout.hybrid.bank`, `synth`, `losses`,
`model`, `train`, `finetune` — are present and covered by
`tests/test_hybrid_synth.py`, `test_hybrid_frames.py` and
`test_hybrid_provenance.py`, including a short end-to-end fine-tune against the
sphere backend that checks the through-solver training gradient actually reaches
the weights. The command-line entry points that drove the full runs are not
shipped here: one of them reaches into a separate research study for its lattice
construction, and this repository is the inference showcase. Nothing in the
demo, the benchmark or either container image needs them.

`tests/test_hybrid_provenance.py` also checks that the network definition inside
the `proposal` component is identical to the orchestrator's, via
`scripts/sync_proposal_component.py --check`. The component carries PyTorch alone
and cannot import the orchestrator package, so the definition is duplicated; that
check is what keeps the duplicate honest.

## The figures and the loop

```bash
make figures       # docs/figures/benchmark.png, seconds
make cortex-mesh   # results/cortex_ico5.npz, needs MNE and fsaverage
make k2-data       # replay the frozen trial to record its trajectories, ~5 min
make k2-visual     # docs/figures/hybrid_k2_visual.gif, seconds
```

`plot_benchmark.py` recomputes its bars from the shards on every run, so the
figure cannot drift from what `make summary` prints. `docs/figures/architecture.png`
is a hand-authored diagram, not a generated artifact: nothing regenerates it, and
`scripts/plot_architecture.py` is an earlier generated version kept for reference
whose output path is a different file. The generated figures share one palette,
in `scripts/showcase_style.py`.

The shards store answers, not paths, so `make k2-data` re-runs the two
refinements of that one trial to record the trajectories. It is a replay, not a
benchmark run: it uses the committed observation, the frozen refinement settings
and the packaged checkpoint, and **refuses to write anything** unless every
reproduced per-source error and sensor residual matches the frozen shard to
0.05 mm and 1e-4. Both outputs, and the mesh, are committed, so neither step is
needed to view the figures.

`make k2-visual` draws eight frames at seven of the twenty-one recorded
checkpoints and one held final frame. It interpolates nothing and recomputes
nothing; it reads the replay artifact and the cortical mesh, and takes a few
seconds. All three outputs are committed, so none of these steps is needed to
view the figures.

## What is not here

No external human dataset is used, needed, or discussed. Every observation in
this repository is synthetic, generated on the fsaverage template anatomy.
